# 文件與契約核對

先界定本次檢查的文件、目標版本，以及來源是工作目錄、固定提交或執行中的 API。以 `git status --short` 區分既有修改；底座有未提交修改時，結論也須註明來源狀態。

對本次範圍內每項重要現況主張，在既有驗證紀錄中列出「文件位置、事實來源、結果、未驗證範圍」。來源須可定位到檔案與章節、固定提交或可重跑的命令。結果使用「已核對」「歷史紀錄」「待驗證」或「不一致」；文件語意與來源的關係由審查者核對。

程式與即時工具表證明實作現況；自動測試證明受控情境；歷史紀錄證明當時結果。分開記錄這些證據，完整接入驗收另列管理 API、身分隔離、Bot／AI／Discord 呼叫與撤權等實際執行結果。只有全部範圍都有證據且差異已解決，才能稱該範圍完成對齊；其餘明列未驗證項目。

純文件修改先執行 `npm.cmd run check:docs`（PowerShell）或 `npm run check:docs`，再執行 `git diff --check`。程式或可執行範例變更另加對應驗證。CI 設定為執行文件檢查及完整測試，以 [CI 定義](../../.github/workflows/ci.yml)為準。

文件檢查掃描 Git 已追蹤與未忽略的新 Markdown，確認 inline 連結（含圖片）及 reference definition 的本地目標存在；跳過程式區塊與行內程式碼。它不驗證外部網址、頁內錨點、reference label 是否有定義、文件主張或完整 CommonMark 語法。新增其他連結語法時，先擴充檢查再依賴它作為關卡。

判準的原因及歷史例子見[文件治理回顧](../devcycle-documentation-governance-retrospective.md)。
