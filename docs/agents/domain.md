# Domain docs

This repository uses a single-context layout: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

Before working in an area, read the relevant glossary terms and ADRs if those files exist. Use the glossary’s terms in issues, proposals, code, and tests. Surface any conflict with an ADR explicitly.

Create glossary entries and ADRs when decisions are made; their absence does not require placeholder files.
